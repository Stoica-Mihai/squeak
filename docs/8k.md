# Protocol: 8k  (plain, non-nordic)

> **Extracted from Launcher JS only; NOT verified on hardware — confirm with
> usbmon before trusting writes.**

Source: `main.4b620e6634d704dd.js`. This is the `default:` branch of every
per-feature `switch(this.action.info.protocol)` (the cases that are not
`"1k"`/`"4k"`/`"8k_nordic"`). Plain 8k has **no dedicated `case"8k"`** in most
switches — it falls through to `default`. Exceptions that *do* test
`"8k"===…protocol` explicitly: DPI X/Y separate (`getXY`), report-rate separate
(`getSeparate`), sleep (`Xo`), light (`ss`/`Kr`), quick-response (disabled).

## Transport

Same HID config collection as nordic (usage page `0xFFC1`).

| Report ID | Dir | Bytes | Role |
|---|---|---|---|
| `0xB3` (179) | OUT | 63 | long command (READ block + long writes) |
| `0xB4` (180) | IN  | 63 | long reply |
| `0xB5` (181) | OUT | 20 | short command (most WRITE settings) |
| `0xB6` (182) | IN  | 20 | short reply |
| `0x00` (0)   | OUT | 64 | NAPE long channel (dongle/receiver info, shared) |

- Short reply marker is `0xE4` (228) `= [E4, status, cmd, …]`, same as nordic.
- `161 - sum(buf[0:63])` (`0xA1` seed) checksum applies only to 64-byte NAPE
  frames written on report id `0`. Short (181) frames carry no checksum.

## READ — settings block (long cmd `0x06`)  — IDENTICAL to nordic

`[0xB3, 0x06]` → reply `0xB4` (`b[0]=0x06`). Launcher class `zt` parses the
**exact same offset map** as nordic's `zt` (see `docs/8k-nordic.md` "READ —
settings block"): profile `b[1]`/`b[50]`, dpi nibbles `b[2..4]`, dpi presets
LE16 `b[5,7,9,11,13]`, dpi count `b[16]`, max LE16 `b[40]`, step `b[42]`,
polling nibbles `b[2..4]>>4`, polling codes `b[43:49]`, sensor `b[15]`,
fps20k `b[52]&1`, angle signed `b[55]`, debounce `b[17]`/`b[30:40]`,
scroll `b[27,28,29]`, sleep `b[18]`, battery `b[19]`, wake `b[51]`,
support flags `b[26]`, plus `b[53]`/`b[60]` feature bits.

**DIFFERENCE — device info chained after the block:** nordic's `zt` chains
`new dt` (long cmd `0`); plain 8k's `zt` chains `new st`, which reads device
info over the **short** channel:

| Class `st` (8k-plain device info) | value |
|---|---|
| write | report `181`, `buf=[0x02, idx]` (short cmd `2`) |
| reply filter | `b[0]===2` |
| version | LE16 `b[1,2]` |
| vid / pid | LE16 hex `b[3,4]` / `b[5,6]` |
| frVersion | `b[8].(b[7]>>4).(b[7]&15)` |
| workMode | `bin2Oct(oct2Bin(b[9]).substring(5))` |

(Nordic reads vid/pid/version via long cmd `0`/`4` with `b[2]=129`.)

Firmware ASCII version reader is class `nn`: long cmd `4` on report `179`,
`buf=[4, idx]`, reply `b[0]===4` → `byteToAscii(b.slice(2, b[1]+2))`. (Nordic
uses long cmd `0` on report `0` instead.)

### Dongle / receiver info (shared, NAPE report `0`)

`buf[0]=64, buf[2]=129, buf[3]=0, buf[63]=161-(buf[0]+buf[2]+buf[3])` →
reply `b[0]===64 && b[3]===0`. Returns receiver state/vid/pid. This frame is
shared with 4k (class `qe`) and used by the protocol auto-detector
(`P[0]=1,P[2]=129,P[3]=1,P[63]=161-…`, then `b[6]==0x34 && b[7]==0x34` ⇒
`8k_nordic`, else `4k`/plain). Identical to nordic.

## WRITE — short channel (report `0xB5`=181), `buf[0]=cmd`

Plain 8k routes most settings to the **same short cmd ids as nordic**. The
table below is the `default`-branch class for each feature.

| cmd | hex | feature | class | payload (buf indices after cmd) | vs nordic |
|---|---|---|---|---|---|
| `64` | 0x40 | **DPI presets** | `io.set` | `[1,2,3]=level`, LE16 presets `@[4..13]`, `[14]=levelNum` | same channel/cmd |
| `65` | 0x41 | **polling rate** | `ms.set` | `[1,2]=level`, codes `@[3..8]`, `[9]=levelNum` | same |
| `74` | 0x4A | **polling rate (separate X/Y)** | `ms.setSeparate` | per-axis: `[1+i]=level,[3+i]=levelNum`, 6 codes `@[5+6i]` | **8k-only** (gated `"8k"===protocol` via `getSeparate`) |
| `75` | 0x4B | polling separate READ | `ms.getSeparate` | reply parsed `b[1..]` | 8k-only |
| `66` | 0x42 | **sensor** | `li.set` | `[1]=lod,[2]=sensor0||2,[3]=sensor1||2,[4]=sensor2||2,[6]=scrollDir+1,[8]=fps20k+1` | same as nordic `En` |
| `66` | 0x42 | **angle snap** | `li.setAngle` | `[9]=enable?2:0,[10]=angle` | **shared** with nordic (`Br.setAngle` default) |
| `67` | 0x43 | **debounce** | `Vt.set` | `[1]=value`; if profile≥0: `[2]=17,[3]=profile,[4]=value` | same |
| `69` | 0x45 | **DPI profile select** (`setWheel`) | `Yo.set` (via `xs`) | `[1],[2],[3]` = the 3 profile indices | gated `"8k"` wrapper |
| `36` | 0x24 | DPI indicator light | `Kr.set` | `[1]=i,[2]=l,[3]=s,[4]=r,[5]=g,[6]=b` | default light class |
| `10` | 0x0A | **sleep timeout** | `ss` (via `Xo`) | get `[1]=2`→`time:b[2]`; set `[1]=1,[2]=secs||255` | gated `case"8k"`; same frame as nordic |
| `15` | 0x0F | **factory reset (selective)** | `Ai.set` | `all`→`[1]=255`; else `[2]=idx,[3]=bitmask{key,dpi,light,sensor,profile,scroll}` | same as nordic `hr`? no — see below |
| `14` | 0x0E | **profile switch** | `Hn.set` | `[1]=profile,[2]=arg||0`; reply `E4,0,0E` | **DIFFERS** (nordic `ui` uses report `0`, cmd `2`, `[2]=130,[3]=2,[4]=profile`) |
| `3`  | 0x03 | receiver/connection state | `ji.get` | get; reply `b[0]===3` 5-byte records | same channel |

`setPollingRate` applies `pollingGearsSupport ? Us(level) : level`. The
report-rate dispatch (`Nt.set` default) chooses
`reportRateSeparateSupport ? ms.setSeparate : ms.set`.
Polling code → Hz is the same dongle table as nordic
(`0=125,1=250,2=500,3=1000,4=2000,5=4000`; 8000 cable-only).

## WRITE — long channel (report `0xB3`=179) — KEY DIFFERENCE FROM NORDIC

Plain 8k pushes **DPI X/Y, buttons, and macros over the long 179 channel**
(raw 63-byte frames, reply marked by `b[0]===228 && b[2]===cmd` or `b[0]===cmd`),
where nordic routes the same features through dedicated nordic classes
(report id `82`, NAPE `setSensorParams`, etc.).

| cmd | hex | feature | class / method | payload |
|---|---|---|---|---|
| `72` | 0x48 | **DPI separate X/Y set** (`dpiSeparateSupport`) | `io.setXY` (ver<6) / `io.setXYV6` (ver≥6) | see below |
| `73` | 0x49 | **DPI separate X/Y read** | `io.getXY` / `getXYV6` | reply `b[0]===73` |
| `82` | 0x52 | **button remap** | `Si.set` | `[1]=type, [3]=index, [4..]=data` |
| `97` | 0x61 | **button list read** | `Qt.getAll` | reply `b[0]===97`, `b[1]`=count, then var-length records |
| `98` | 0x62 | **single button read** | `Qt.get(idx)` | `[1]=idx`; reply `b[0]===98 && b[1]===idx`, `b[3]`=type, `b[4..]`=data |
| `84` | 0x54 | **macro set** | `vr.set` | `[1]=index,[2]=0,[3,4]=len+6 LE16,[5]=1,[6,7]=loopMode<<13\|loopNum,[8,9]=delay,[10]=macro.length`, then bytes |
| `113`/`114` | 0x71/0x72 | **macro long-data chunking** | `vr.sendLongData` | `[0]=113,[1]=seq<<2\|more,[2]=chunkLen,[3..]=59-byte chunks`; reply `b[0]===114` |

`io.setXY` (ver<6): `buf[0]=72`; `mergeLevelBytes` packs Y<<4|X into `[1..3]`,
`[4]=levelNum`, X presets LE16 `@[5..]`, Y presets LE16 `@[21..]`, enable bytes
`@[37..]`.
`io.setXYV6` (ver≥6): `buf[0]=72`; `[1,2,3]=level`, `[4]=levelNum`,
X presets LE16 `@[5..]`, Y presets LE16 `@[21..]`, `[37]=enable bitmask`.

Button helpers on `Si`: `.basic` (Mouse, 3-byte HighToLow), `.keyboard`
(modifier sum + keycodes), `.media`, `.dpi`, `.pollingRate`, `.game`.

## Factory reset — `Ai` (cmd `15`, short 181)

`Ai.set(ze, Ye="all")`: `buf[0]=15`. `ze.all` ⇒ mask `255`; else
`mask = key|dpi<<1|light<<2|sensor<<3|profile<<4|scroll<<5`.
`Ye==="all"` ⇒ `[1]=mask`; else `[2]=Ye, [3]=mask`. Same shape as the nordic
short-channel reset; the dispatcher (`Vi.set`) sends 4k/8k_nordic to the
NAPE `hr` class but plain 8k to this `Ai` short-channel class.

(The `gs` class with `buf[0]=11` writing report id `81` is the **1k** reset
path, not 8k.)

## Save / commit — NONE

`rt.set` (`default` branch, plain 8k) logs *"8k doesn't need save config
command"* and sends nothing. Plain-8k writes take effect immediately. This is
a **difference from nordic/4k**, which call `ut.set` to persist.
`saveProfile` likewise has no plain-8k path.

## Battery / version

Battery % is in the cmd-`06` block (`b[19]&127`, charging `b[19]>>7`), same as
nordic. Version/vid/pid additionally available via short cmd `2` (`st`, above)
and ASCII firmware via long cmd `4` (`nn`).

## Quick-response / wake-origin

`fs.set` (quick-response) returns `of(null)` for plain 8k — **not supported**
(only `8k_nordic` routes to `Mo`→`setSystemParams({quickResponse})`).
Wake-origin (`rouseOrigin`) flags are still parsed in the cmd-`06` read
(`b[51]` bits 4/5/6/7) but have no plain-8k write path in this bundle.

## Buttons / macros / gestures

Unlike nordic (which uses the QMK-raw `0xFF60` NAPE/VIA path for advanced
remaps), plain 8k handles buttons (`Si`, cmd 82) and macros (`vr`, cmd 84 +
113/114 chunking) **directly on the long 179 config channel** documented above.
No separate `0xFF60` collection is required for the basic button/macro set on
plain 8k.

## Summary of differences vs `8k_nordic`

| Feature | 8k_nordic | 8k (plain) |
|---|---|---|
| settings READ | long cmd 6 (class `zt`) | long cmd 6 (class `zt`) — **same offsets** |
| device info | long cmd 0/4, `b[2]=129` (`dt`) | **short cmd 2 on report 181** (`st`) |
| DPI presets | short cmd 64 | short cmd 64 — same |
| DPI X/Y separate | NAPE `setSensorParams` | **long cmd 72/73** (`io`) |
| polling | short cmd 65 | short cmd 65; **separate via cmd 74/75** |
| sensor | short cmd 66 (`En`) | short cmd 66 (`li`) — same |
| angle snap | short cmd 66 `[9][10]` | short cmd 66 `[9][10]` — **shared class** |
| debounce | short cmd 67 | short cmd 67 — same |
| profile switch | report 0, cmd 2, `[2]=130` (`ui`) | **short cmd 14** (`Hn`) |
| DPI profile select | (nordic class) | **short cmd 69** (`Yo`/`xs`) |
| buttons | report id 82 (`Pi`/`wi`) | **long 179 cmd 82** (`Si`) + read 97/98 |
| macros | NAPE cmd 85 (`Di`) | **long 179 cmd 84** + 113/114 (`vr`) |
| factory reset | NAPE `hr` | **short cmd 15** (`Ai`) |
| quick-response | supported (`Mo`) | **not supported** (`of(null)`) |
| save/commit | `ut.set` | **none** ("no save needed") |
| sleep | short cmd 10 | short cmd 10 — same (gated `case"8k"`) |
| light/DPI color | short cmd 36 | short cmd 36 (`Kr`) — same |
