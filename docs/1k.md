# Protocol: 1k  (mouse)

> **Extracted from Launcher JS only; NOT verified on hardware — confirm with
> usbmon before trusting writes.**

Reverse-engineered from `main.4b620e6634d704dd.js`. The Launcher dispatches per
protocol with `switch(this.action.info.protocol){case"1k":…case"4k":…default:…}`;
the `case"1k"` branches name the command classes below. Unlike 8k, 1k reports
all `support` flags **false** (no profiles, no save, no polling-gears) — see
notes.

## Transport

1k uses three report ids. Settings ride the **short** channel (report `0x51`);
buttons/macros ride a **long** 64-byte channel (report `0x52`).

| Report ID | Dir | Bytes | Role |
|---|---|---|---|
| `0x51` (81) | OUT | 20 | short command (READ trigger + WRITE settings) |
| `0x51` (81) | IN  | 20 | short reply (echoes `buf[0]=cmd`) |
| `0x52` (82) | OUT | 64 | long command (buttons / macros) |
| `0x52` (82) | IN  | 64 | long reply |

- Short command: `write(81, buf)` with `buf[0]=cmd`. Reply arrives on the same
  report id; handlers filter on `reply[0]===cmd`.
- Short-reply ACK marker: some setters filter `reply[0]===228` (`0xE4`) and read
  `reply[1]` as status (`0===OK`). Same `0xE4` short-reply convention as 8k.
- The optional 3rd arg to `write(81, buf, 3)` / `write(82, buf, 1|3)` is a
  transfer/sequence flag (used by light + macro multi-frame writes), not a payload byte.
- No checksum on short (20-byte) frames. (The `161-sum` NAPE checksum is 8k/4k only.)

`numToHighLow(n, len=2, bits=8, "LowToHigh")` = little-endian split; default is
LE16. `[…,3,8,"HighToLow"]` = 3-byte big-endian (used for mouse-button keycodes).

## READ — settings block (short cmd `0x07`)

Class `at`: `Ye[0]=7; write(81,Ye)` → reply filtered on `reply[0]===7`. Body
`b[]` (report id stripped, `b[0]=0x07`). Field map:

| Field | Offset / formula | Notes |
|---|---|---|
| profile.current | `b[1]` | levelNum forced =1 |
| dpi.level[0..2] | `b[2]&15, b[3]&15, b[4]&15` | low nibble = active dpi idx |
| dpi.presets[5] | LE16 @ `b[5,7,9,11,13]` | `b[6]<<8\|b[5]`, … `b[14]<<8\|b[13]` |
| dpi.levelNum | `b[16]` | preset count |
| polling.level[0..2] | `b[2]>>4&15, b[3]>>4&15, b[4]>>4&15` | high nibble = rate code; levelsVal hard-coded `[0,1,2]`, levelNum=3 |
| sensor.lod | `b[15] & 3` | lift-off distance |
| sensor.wave | `b[15] & 4` (bit2) | ripple control |
| sensor.line | `b[15] & 8` (bit3) | angle straightening |
| sensor.motion | `b[15] & 16` (bit4) | motion sync |
| sensor.scrollDir | `b[15] & 64` (bit6) | invert scroll |
| sensor.fps20k | (forced 0) | not in 1k block |
| sensor.angle | (forced 0) | not in 1k block |
| debounce.value | `b[17]` | ms |

### READ — device info (short cmd `0x06`)

Class `Ee`: `Ye[0]=6; write(81,Ye)` → reply `reply[0]===6`:

| Field | Offset / formula |
|---|---|
| version | LE16 @ `b[1]` (`b[2]<<8\|b[1]`) |
| vid | LE16 hex @ `b[3]` (`b[4]<<8\|b[3]`) |
| pid | LE16 hex @ `b[5]` (`b[6]<<8\|b[5]`) |
| frVersion | `${b[8]}.${b[7]>>4&15}.${b[7]&15}` |
| workMode | `bin(b[9])` bits 5.. |
| power.value | `b[10]` |
| power.state | `b[11] & 3` |
| loopDPressSupport | `b[13] & 1` |

### READ — other short reads

| cmd | hex | class | reply parse |
|---|---|---|---|
| `4` | 0x04 | `xt` | firmware version ASCII: `reply.slice(2, reply[1]+2)` |
| `3` | 0x03 | `Ur` | receiver/bond list: count `b[1]`, then 5-byte records from `b[2]`: vid `b[3+5i]b[2+5i]`, pid `b[5+5i]b[4+5i]`, state `b[6+5i]` |
| `54` | 0x36 | `ro` | pair-key / loop-double-press: if `b[1]===0` defaults, else bits of `b[1]` = left/right/middle/forward/backward; `time=b[2]` |
| `18` | 0x12 | `Dr` | light: returns active light index in `b[3]`, then issues cmd `24` |
| `24` | 0x18 | `Dr` | light detail: mode arg, `brightness=b[5], speed=b[6], rgb=[b[2],b[3],b[4]]` |

## WRITE — short channel (report `0x51`), `buf[0]=cmd`

| cmd | hex | class | feature | payload (buf indices after cmd) |
|---|---|---|---|---|
| `64` | 0x40 | `_o` | **DPI presets** | `[1]=[2]=[3]=level`; LE16 of `levelsVal[]` @ `[4..13]` (`numToHighLow`); `[14]=levelNum` |
| `65` | 0x41 | `Ko` | **polling rate** | `[1]=[2]=min(level,2)`; `levelsVal[]` @ `[3..]` raw |
| `66` | 0x42 | `En` | **sensor** | `[1]=lod, [2]=sensor[0]\|\|2 (wave), [3]=sensor[1]\|\|2 (line), [4]=sensor[2]\|\|2 (motion), [6]=scrollDir+1` |
| `67` | 0x43 | `ct` | **debounce** | `[1]=value`; if `Ye>=0` (profile): `[2]=17, [3]=Ye, [4]=value`. Reply filter `228 && reply[2]===67` |
| `70` | 0x46 | `ro` | **pair-key / loop double-press** | `[1]=mode\|\|17, [2]=time\|\|0`. ACK `228 \|\| reply[2]===11` |
| `11` | 0x0B | `gs` | **factory reset (selective)** | `all`→`[1]=170`; else `[1]=1, [2]=bitmask` of `{key:b0, dpi:b1, light:b2, sensor:b3}` (`reduce(\|, v<<i)`) |
| `34` | 0x22 | `Dr` | light: mode | `[1]=1, [2]=mode`. `write(81,_,3)` |
| `35` | 0x23 | `Dr` | light: brightness (L) | `[1]=1, [2]=value, [3]=mode` |
| `39` | 0x27 | `Dr` | light: speed (S) | `[1]=1, [2]=value, [3]=mode` |
| `40` | 0x28 | `Dr` | light: color (C) | `[1]=1, [2]=mode, [3]=r, [4]=g, [5]=b` |

### Not supported on 1k (JS short-circuits with a console warning)

| feature | behavior in JS |
|---|---|
| save / commit | `console.warn("1k 不需要保存配置指令")` — **no save cmd; writes are immediate** |
| profile switch | `console.error("1k 暂不支持切换Profile配置")` / `Pi.profile()` logs `"1k 无Profile改建功能"` — no-op |
| angle snap | 1k breaks out of the angle switch (no cmd) |
| sleep timeout | no 1k branch (8k/default only) |
| DPI-level select (cmd 69) | no 1k branch |

## Buttons / macros — long channel (report `0x52`)

Class `Pi` (button assignment), `Ct` (button read), `zr` (macros). Button slots
are indexed `ze`; the value type is the `S` enum:

`S = {Remove:0, Mouse:1, Keyboard:2, Media:3, Macro:4, Dpi:5, Light:6, Game:7, ShortCut:8, Disable:9, Profile:10, PollingRate:13}`

### WRITE button — class `Pi.set(idx, type, data[])` → cmd `0x52` (82)

`buf[0]=82, buf[1]=type, buf[3]=idx, buf[4..]=data` (64-byte frame).

| method | type | data layout |
|---|---|---|
| `basic(idx, key)` | Mouse(1) | 3-byte big-endian mouse keycode (`numToHighLow(n,3,8,"HighToLow")`) |
| `keyboard(idx, mods[], keys[])` | Keyboard(2) | `[modmask, key0, key1]` (modmask = sum of `b[mod]`) |
| `media(idx, key)` | Media(3) | LE16 of media code |
| `dpi(idx, key)` | Dpi(5) | `[v[key]]` |
| `pollingRate(idx, key)` | PollingRate(13) | `[v[key]]` |
| `game(idx, {count,rate,code})` | Game(7) | `[mouse\|kbd, code, LE16(rate), LE16(count)]` |
| `shortCut(idx, key)` | ShortCut(8) | 3-byte big-endian shortcut code |
| `remove(idx)` | Remove(0) | (none) |
| `disable(idx)` | Disable(9) | (none) |

### READ buttons — class `Ct`

- `getAll()`: cmd `97` (0x61) → reply `reply[0]===97`; active slots = nonzero in
  `reply[1..9]` ∪ `reply[33..40]`; then `get(idx)` per slot.
- `get(idx)`: cmd `98` (0x62), `buf[1]=idx` → reply `reply[0]===98 && reply[1]===idx`;
  `type=S[reply[3]]`, payload from `reply.slice(4)` decoded per type (see `accountKey`).

### WRITE macro — class `zr.set({index, loopMode, loopNum, delay, macro[][]})` → cmd `0x52`

Multi-frame, each frame 64 bytes, `buf[0]=85` (0x55):

- `buf[1]=index`, `buf[2]=0` on last frame else `1`, `buf[5]=length-this-frame`.
- First frame: `buf[6]=1, buf[7..8]=LE16(loopMode<<13 \| loopNum), buf[9..10]=LE16(delay), buf[11]=macroLen/4`, then macro bytes from `buf[12]`.
- Continuation frames: `buf[3..4]=LE16(byteOffset+6)`, then macro bytes from `buf[6]`.
- Last frame written with seq flag `3`, others with `1`.

## Live monitor — class `Ht.open()` (report `0x52` IN, unsolicited)

| reply[0] | event | fields |
|---|---|---|
| `225` (0xE1) | monitor-light | `mode=b[1], speed=b[3], brightness=b[4], rgb=[b[5],b[6],b[7]]` |
| `226` (0xE2) | monitor-base | `workMode=b[1], connect=(b[2]===1), power={state:b[3],value:b[4]}, dpi={level:b[5],levelNum:b[7]}, pollingRate={level:b[6]}` |

## Notes / caveats

- All `support` flags in the `at` READ reply are hard-coded `false` for 1k
  except `loopDPressSupport` (from cmd-6 `b[13]&1`) and `pairKeySupport=true`.
- Writes take effect immediately; there is **no save/flush** step on 1k.
- DPI presets write LE16 (`numToHighLow`), but the READ block parses them LE16 as
  well (`b[hi]<<8|b[lo]`) — consistent.
- Polling-rate write sends raw level (no `pollingGears` remap on 1k).
- Command/report-id values verified against the JS source; **byte semantics
  (units, valid ranges, ACK timing) are unverified — capture usbmon before
  relying on any WRITE.**
